# Зависимости и совместимость

Устанавливайте Python-зависимости через `uv sync --frozen --group dev`,
JavaScript-зависимости — через `npm ci` в `apps/web` и `apps/admin`.
Зафиксированные версии находятся в `uv.lock` и соответствующих `package-lock.json`.

## Remnawave

Используется пакет `remnawave` версии `2.8.0`. В его модели HWID по-прежнему
обязательно поле `userUuid`, хотя панель 2.8 возвращает `userId`.
Поэтому операции HWID используют HTTP-клиент SDK с нашей моделью нужных полей.
Поддерживаются оба формата ответа; запросы остаются привязаны к UUID пользователя.
Успешное удаление не разбирается через несовместимую модель SDK.

Совместимость проверяется JSON-ответами панели в тестах интеграции и
`GET /api/v1/devices`. Переход на API панели 3.x требует отдельной проверки
пользовательских идентификаторов и операций создания/обновления пользователей;
равенство номеров панели и SDK само по себе не гарантирует совместимость.

Старый SDK ограничивает `cryptography` версией ниже 47. В `[tool.uv]` задано
исключение `cryptography>=50.0.0,<51`, чтобы использовать исправленную версию.
Единственное обращение SDK к этому пакету — RSA-шифрование ссылок Happ;
тест проверяет оба формата ссылок, v3 и v4. При замене SDK пересмотрите исключение.
Ограничение SDK на `httpx<0.28` сохраняется.

## Проверки после обновления

- Полные Python-тесты API и бота, Ruff и покрытие критичных частей API.
- Lint, typecheck, unit-тесты, браузерные тесты и сборка обоих интерфейсов.
- `npm audit` в обоих интерфейсах.
- `uvx pip-audit --path .venv/Lib/site-packages` в Windows; в Linux используйте
  каталог `site-packages` своей виртуальной среды.

Для локального запуска Python в Windows зависимость `tzdata` устанавливается
отдельным маркером платформы. Серверные Linux-образы этот пакет не требуют.
