# RemnaStore 1.2.0

## Подписки для аккаунтов без email

- Исправлена ошибка валидации SDK Remnawave при выдаче trial и платной
  подписки пользователям VK ID без email. Пустая строка и пробелы считаются
  отсутствующим адресом, фиктивная почта не создаётся.
- Обновление без нового email сохраняет существующий адрес в Remnawave
  и локальном аккаунте. Ошибки DTO обрабатываются как ошибки интеграции.
- Регрессионные проверки охватывают повтор trial после ошибки и покупку
  из кошелька с повторным idempotency key без двойного списания.

## Сброс пароля и вход через Яндекс ID

- После recovery-перехода приоритет получает форма нового пароля. Учтены
  события Supabase, PKCE, перезагрузка вкладки и поздние ответы загрузки кабинета.
  Старая сессия не подменяет недействительную ссылку сброса.
- Сохранение проверяет recovery-сессию. Ошибка допускает повтор, истёкшая
  ссылка предлагает запросить письмо заново. Отмена завершает локальную сессию.
- Для Яндекса адаптер доверяет email только при совпадении с серверным
  почтовым логином в доменах yandex.ru, ya.ru, yandex.com, yandex.by, yandex.kz.
  Прочие контакты могут требовать подтверждения Supabase. Общее подтверждение
  почты не отключается.
- Настройки клиента показывают сохранённые способы входа Google, Яндекс ID
  и VK ID, включая аккаунты без почты. В карточке админки уточнены названия
  провайдеров; переработка админки в этот выпуск не входит.

## Общая оплата и СБП для одного платежа

- Подготовлена отдельная страница с виджетом ЮKassa: общий выбор способов
  и прямой режим СБП используют один payment.id и confirmation_token.
  Переключение и повторное открытие не создают новый платёж.
- Для перехода из Telegram во внешний браузер используется ограниченная
  ссылка только на этот платёж, сроком до часа. Она не даёт доступа к кабинету.
  Оплаченный, отменённый или просроченный платёж повторно не открывает форму.
  Итог начисления определяется существующей серверной обработкой webhook/сверки.
- По умолчанию функция выключена: `YOOKASSA_WIDGET_ENABLED=false`. При
  включении новые платежи используют embedded-виджет на нашей странице,
  поэтому общая ссылка также меняется. Старые redirect-платежи сохраняются.
  Это подготовленная альтернатива двум внешним ссылкам ЮKassa; поддержка
  точного исходного сочетания внешних ссылок не подтверждена.

## Настройки и проверка перед включением

Миграции БД не требуются. Рабочий `.env` сохраняется. Новый флаг находится
в `env.example`, его читает API через существующий `env_file` Compose:

```env
YOOKASSA_WIDGET_ENABLED=false
```

Для будущего включения нужен корректный `WEBAPP_URL` на frontend с маршрутом
`/checkout`, а не ссылка на бота. Сначала подтвердите у менеджера ЮKassa
доступность `customization.payment_methods=['sbp']` для магазина, затем
проверьте обычную оплату и СБП на desktop, мобильном устройстве и из Telegram.
Само обновление версии флаг не включает.

Настоящие первый/повторный OAuth-входы, переход ранее неподтверждённого
пользователя Яндекса и сброс пароля с доставленным письмом ещё требуют ручной
проверки на отдельной тестовой установке. Автоматические проверки используют
подменённые ответы провайдеров. Инструкции включены во вложения выпуска:
`auth-recovery-email.md`, `yandex-id.md`, `vk-id.md`, `sbp-checkout.md`.

Изменения подготовлены локально. Развёртывание работающих сервисов выполняется
только по отдельной команде владельца.
