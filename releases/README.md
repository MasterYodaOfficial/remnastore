# Подготовка выпуска

1. Обновите корневой `VERSION`, например `1.0.0` → `1.0.1`.
2. Добавьте `releases/<версия>.md` с русским описанием. Первая строка —
   `# RemnaStore <версия>`, далее — изменения, обновление и важные условия.
3. Включите оба файла в PR. Через `dev` подготовьте PR в `main`.
4. В PR в `main` номер должен быть больше номера в `main` и опубликованных тегов.
5. После слияния в `main` общий CI проверит код и соберёт четыре образа.
   Затем он опубликует номерные образы, обновит `*-latest` и создаст GitHub Release
   `v<версия>` с текстом из Markdown-файла и файлами для установки.

Во вложениях выпуска: `compose.yml`, `env.example`, `VERSION`, `images.json`,
`yandex-id.md` и `configure_yandex_auth.py` — инструкция и скрипт ручной
настройки Яндекс ID. Наличие скрипта во вложениях не запускает его автоматически.
Скачивайте `env.example` как `.env.example`; рабочий `.env` сохраняется.

Описание не переводится из коммитов автоматически: готовый русский текст
пишется вместе с изменениями и просматривается в PR. Внешние рассылки в этот
процесс не входят.

Для исправлений увеличивайте третье число, для совместимых новых возможностей —
второе, для несовместимых изменений — первое. Поддерживаются стабильные номера
`X.Y.Z` без префикса `v` в `VERSION`.

Если публикация прервалась, используйте **Re-run failed jobs** в GitHub Actions.
Уже загруженные номерные образы того же коммита используются повторно.
Образы другого коммита под тем же номером не перезаписываются.
Завершённый выпуск при повторном запуске пропускается.

Ручной повтор всего CI доступен через **Actions → CI → Run workflow → main**.
Публикуется только текущая вершина `main`. Старый завершившийся запуск не
может вернуть `latest` назад. Несколько публикаций выполняются последовательно.

При ошибке обновления `*-latest` публикация пытается восстановить их предыдущие
значения. Обновление четырёх тегов в Docker Hub не является атомарным; для
строго согласованного развёртывания используйте `REMNASTORE_VERSION=X.Y.Z`.

Служебные версии Python/npm-пакетов не определяют номер выпуска Docker.
Источник номера выпуска — `VERSION`; в образы записываются версия и SHA коммита.
