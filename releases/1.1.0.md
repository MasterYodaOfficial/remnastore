# RemnaStore 1.1.0

## Вход через Яндекс ID

- Добавлена интеграция Яндекс ID через custom-провайдер Supabase Auth:
  кнопка входа, адаптер профиля, обработка ошибок и сохранение связи
  с существующим аккаунтом, включая Telegram.
- Адаптер проверяет, что токен выдан нашему приложению Яндекса. Он не выдаёт
  сессии и не объявляет email подтверждённым: сессией и подтверждением почты
  управляет Supabase.
- Кнопка по умолчанию скрыта. Полный вход с реальным аккаунтом Яндекса
  и доставка письма подтверждения пока не проверены; обновление версии само
  по себе не включает новый способ входа.

## Вход через VK ID

- Добавлена интеграция VK ID через `custom:vk` в Supabase Auth: кнопка входа,
  серверный OAuth-мост, PKCE S256 и одноразовые state/коды в Redis.
  Мост передаёт необходимые VK параметры `device_id` и получает профиль
  через POST; обычную пользовательскую сессию выдаёт Supabase.
- Повторный вход сопоставляется с существующей identity VK, сохраняя
  привязку Telegram. Email необязателен и не объявляется подтверждённым.
- Кнопка выключена по умолчанию. Реальный вход требует регистрации
  приложения VK ID, настройки custom-провайдера и проверки полного сценария.

## Настройки и обновление

Миграции БД не требуются. В опубликованный `env.example` включены:

```env
YANDEX_OAUTH_CLIENT_ID=
VITE_YANDEX_AUTH_ENABLED=false
VITE_VK_AUTH_ENABLED=false
VK_OAUTH_CLIENT_ID=
VK_OAUTH_BRIDGE_SECRET=
VK_OAUTH_CALLBACK_URL=https://api.example.com/api/v1/auth/vk/callback
VK_OAUTH_SUPABASE_CALLBACK_URL=https://your-project-ref.supabase.co/auth/v1/callback
```

`YANDEX_OAUTH_CLIENT_ID` задаётся в окружении API. Флаг frontend передаётся
через Compose в `runtime-config.js`, пересобирать web ради смены флага не нужно.
Client Secret настраивается только в Supabase Auth и не передаётся во frontend.
Рабочий `.env` нужно сохранить, добавив новые переменные вручную.

Перед включением требуются регистрация приложения Яндекса, настройка callback,
провайдера `custom:yandex` и доступного для Auth адреса адаптера
`/api/v1/auth/yandex/userinfo`. Для self-hosted GoTrue в инструкции отдельно
описан `GOTRUE_CUSTOM_OAUTH_EXTERNAL_URL`; эта настройка относится к окружению
самого Auth, а не контейнера API.

Во вложения выпуска добавлены `yandex-id.md` и `configure_yandex_auth.py`.
Скрипт запускается вручную на хосте Auth: по умолчанию создаёт выключенный
провайдер, для включения требуется `--enable`. До проверки настоящего входа
оставьте `VITE_YANDEX_AUTH_ENABLED=false`.

Для VK ID нужна инструкция `vk-id.md`, также включённая во вложения выпуска.
`VK_OAUTH_BRIDGE_SECRET` — отдельный случайный секрет (32+ символов), общий
только для API и Supabase, не Client Secret приложения VK. В VK регистрируется
callback API-моста, в Supabase — endpoints `/api/v1/auth/vk/*` с включённым PKCE.
Необходим настроенный `REDIS_URL` и Redis 6.2+ (штатный Compose использует 7).
При сбое Redis вход закрывается с 503. До проверки настоящего входа оставьте
`VITE_VK_AUTH_ENABLED=false`; новые переменные сами по себе не включают провайдер.

После отдельного решения об обновлении используйте согласованные образы
выпуска `1.1.0` для всех сервисов (`REMNASTORE_VERSION=1.1.0`, если версия
закреплена). Работающая установка и Auth автоматически этим PR не меняются.

## Проверки

- Браузерные проверки CI закреплены на Ubuntu 24.04, совместимой
  с установленным Playwright 1.56.1; обновление `ubuntu-latest` до 26.04
  больше не мешает установке Chromium для web и admin.
- Добавлены проверки адаптера и сохранения существующего аккаунта,
  сценарии запуска OAuth с PKCE, сохранения referral intent и ошибок callback.
- Настройка провайдера и повторный запуск скрипта проверены без обращения
  к рабочему Auth; секреты не выводятся в сообщения об ошибках.
- Настоящий OAuth-вход, подтверждение email, конфликты identities и регрессии
  Google/email/recovery нужно проверить на отдельной тестовой установке.
- Для VK проверяются обмен кода, PKCE, истечение и однократность state/кодов,
  сбои Redis/VK, отсутствие email, сопоставление identity и запуск входа
  с сохранением referral intent в мобильном и широком браузерном интерфейсе.
