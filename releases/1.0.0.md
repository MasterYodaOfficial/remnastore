# RemnaStore 1.0.0

Первый выпуск с единым номером версии для API, бота, кабинета и админки.

## Что нового

- Тарифы хранятся в базе данных и настраиваются в админке без перезапуска.
- В настройках кабинета можно посмотреть устройства, удалить одно или сбросить все.
- Можно докупить дополнительные места до общей даты окончания подписки и выбрать,
  сколько мест оставить при следующем продлении.
- Стоимость дополнительного места за каждый срок тарифа задаётся в админке.
- Образы Docker доступны по фиксированной версии и по тегам последнего выпуска.

## Как обновиться

В `.env` выберите последний стабильный выпуск:

```env
REMNASTORE_VERSION=latest
```

Или закрепите эту версию:

```env
REMNASTORE_VERSION=1.0.0
```

Для общей настройки версии удалите старые переменные `API_IMAGE_TAG`,
`BOT_IMAGE_TAG`, `WEB_IMAGE_TAG`, `ADMIN_IMAGE_TAG`: они имеют приоритет.
Затем выполните:

```bash
curl -fsSL -o compose.yml https://github.com/MasterYodaOfficial/remnastore/releases/download/v1.0.0/compose.yml
docker compose pull && docker compose up -d --wait
```

Вложения `compose.yml` и `env.example` соответствуют этому выпуску.
Файл `.env.example` используется как образец: действующий `.env` с ключами
и доступами заменять им не нужно.

## Перед первым обновлением

- Сделайте резервную копию PostgreSQL: API автоматически применяет миграции БД.
- Если вы меняли тарифы в JSON старого контейнера, сначала сохраните его и
  выполните перенос по инструкции `docs/deploy-vds.md`.
- Перед продажей дополнительных устройств проверьте HWID на своей панели
  Remnawave и задайте цены в админке. Пустая цена отключает продажу.
- Удаление регистрации устройства не блокирует его навсегда: при повторном
  обращении оно может появиться снова.
- Возврат к старым образам не отменяет миграции БД; откат требует отдельной
  проверки совместимости и плана восстановления.
