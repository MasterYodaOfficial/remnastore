# RemnaStore 1.2.1

## Исправление открытия оплаты ЮKassa

- Страница `/checkout` теперь получает данные платежа по подписанной ссылке
  без сессии личного кабинета. В 1.2.0 запрос ошибочно попадал под общую
  проверку авторизации и возвращал `401 missing credentials` до проверки ticket.
  Это мешало открыть форму оплаты, в том числе во внешнем браузере из Telegram.
- Только endpoint чтения checkout вынесен из группы авторизации кабинета.
  Проверки подписи, срока ссылки, принадлежности платежа и блокировки аккаунта
  сохранены. Создание платежей, список, тарифы и проверка статуса по-прежнему
  требуют пользовательскую сессию.
- Добавлены регрессионные проверки реальных зависимостей API без подмены
  авторизации: действительная ссылка, неверная подпись, истечение срока,
  другой владелец, блокировка и сохранение защиты остальных endpoints.

## Две кнопки для одного платежа

- На странице оплаты и в незавершённых widget-платежах доступны две карточки:
  «Картой и другими способами» и «СБП». Общая форма показывает доступные
  магазину способы ЮKassa, СБП открывает режим оплаты через приложение банка.
- Выбранный режим выделяется. Переключение использует прежние `payment.id`
  и `confirmation_token`, новый платёж не создаётся. Старые redirect-платежи
  сохраняют прежнюю кнопку продолжения оплаты.
- Восстановлен читаемый русский текст ошибок изменения стоимости и повторного
  использования ключа оплаты с другими параметрами, включая Telegram Stars.

## Обновление и ограничения

Миграции БД и новые настройки не требуются. Существующий `.env` сохраняется,
`YOOKASSA_WIDGET_ENABLED` остаётся выключенным по умолчанию. Если владелец
уже включил виджет, после обновления используется его текущее значение.

Исправление `401` не подтверждает доступность отдельного режима СБП у магазина.
Разрешение ЮKassa на настройку способов оплаты, реальный QR, выбор банка
и возврат после оплаты требуют отдельной проверки. При недоступности режима
СБП можно перейти к общей форме того же платежа.

Слияние PR выпускает образы по существующему процессу; развёртывание сервера
выполняется только по отдельной команде владельца.
